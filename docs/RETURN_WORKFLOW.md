# 退货操作流程与数据保护

本流程适用于本次退货修复后的版本。正常退货由业务员录入、管理员确认实物并审核；实际退款由管理员单独登记。系统不会自动付款，也不会把退货余额自动抵到其他销售单。

## 正常退货

1. 打开原销售单，点击“办理关联退货”；也可以进入“退货管理 → 新建退货单”，按单号或客户查找并选择已审核原销售单。
2. 从原销售明细中选择商品，只填写实际退货数量、实际退回仓库、日期、原因和备注。客户、单价、单位、箱规、成本沿用原明细。涉及多张销售单时分别开退货单。
3. 按原单单位填写整数数量。原单按箱销售的普通退货按整箱办理；拆箱、单位不一致及找不到原单的情况交管理员核实，不自行换算或改价。
4. 录入后可以“存草稿”，准备好再提交审核。审核前允许撤回修改；此时不会增加库存，也不会减少应收。页面提示“本机暂存”的内容尚未保存到服务器。
5. 管理员检查原单、客户、实际收到的可售商品、数量和退回仓库。实物未收到或数量不一致时不要审核。勾选收货确认后，点击“确认收货并审核”。
6. 审核成功后，系统同时记录退货库存、冲减原单销售金额、更新原单应收或待退款、追加客户对账流水和审计。任何一步失败，整次操作回滚。
7. 查退货详情及原销售单核对结果。已审核退货的客户、原单、明细、金额和成本固定；有退货入账历史的原销售单也不能反审核改写。

## 欠款与实际退款

固定规则：先抵原单欠款，剩余才成为待退款。实际退款不会在退货开单时录入。

原销售额均为 1000 元，本次退货 400 元：

| 原单已收现金 | 抵原单欠款 | 待实际退款 |
| ---: | ---: | ---: |
| 600 元 | 400 元 | 0 元 |
| 800 元 | 200 元 | 200 元 |
| 1000 元 | 0 元 | 400 元 |

- 可退现金为 0 时，不再登记退款；通过抵欠款完成结算的退货显示“已抵扣欠款”或“已结清”。
- 实际把款项付给客户后，在退货详情填本次实际退款金额、银行/支付流水号或现金付款确认说明，再点击“登记实际退款”。
- 可以分次退款。系统同时校验本退货剩余额度及原销售单当前待退款余额，超额会拒绝。
- 退款金额、凭据、经办人、登记时间、审计和对账流水一起保存。相同提交的重试不会再记一次退款。
- 日期口径：退货单日期是单据业务日期；对账按实际登记入账日期。退款凭据中的真实付款日期可以写在说明中。系统不伪造历史支付流水，也不自动改写以前的对账单。

## 无原单或特殊退货

只有管理员可以选择“无原销售单：管理员例外办理”。必须填写原凭证、客户确认、数量与价格的核实依据，再录明细。

例外退货独立记账，不会自动抵任何销售单的欠款。请不要为了绕过正常退货的限额或单位限制而选择此入口。

破损、过期、待检货不得作为可售货直接审核入库。本次普通退货流程只处理收到的可售商品。特殊库存处置交管理员核实并另行留痕处理；不要用正常退货把坏货加到可售库存。

## 录错后的处理

### 审核前

撤回为草稿，核对后修改并重新提交。被拒绝且从未入账的退货可由管理员重新提交，再撤回修改。

### 审核后、尚未退现金

由管理员打开“录错了：留痕撤销后重开”：

1. 核实原收货记录确实有误，或者货物已实际退回客户；不能仅为了换原单而扣减实际仍在库的货。
2. 填撤销原因，勾选库存撤销确认。
3. 库存必须足够扣回退货数量。系统按商品合计检查，不能扣成负库存。
4. 确认撤销后，系统追加反向库存和当日退货冲销对账流水，保留原退货明细、原单归属、原因和审计。
5. 撤销记录不能重新编辑或重新审核。核对后另开新退货单；原销售单的历史仍保留并锁定。

同一撤销提交重试只冲销一次；重复审核也不会重复入库。

### 已退现金、库存不足或实物去向不清

系统阻止撤销，避免消除真实退款或制造虚假库存。保留原记录，由管理员先核对客户付款凭据、实际货物和后续出库业务。本版不提供已退款退货的自动撤销、退款反向记账或跨单抵扣；不能用反审核、改旧单或直接修改数据库绕过。

## 历史数据与升级保护

- 新迁移只新增流程字段、退款凭据表和对账归属快照，不重写旧销售/退货金额、成本快照、已收/已退现金、库存数量或已有流水。
- 旧逐笔退货对账优先从该次操作的审计快照还原当时原单，后续不再根据退货单的当前关系重新分组。
- 旧账升级结转保持升级时的业务余额，不重建无法获知的历史分次收退款。
- 历史退货流水缺少可还原审计时，保留金额并固定可获得的归属，在相关客户对账单明确提示管理员核对，不把推测当作已验证历史。
- 曾经入账的旧退货也会锁定，不能通过反审核改关联、改客户或改明细来改变历史账。
- 旧草稿和待审核单据保留原值；管理员审核时仍需确认实物。无原单的旧待审核退货需先撤回并补齐例外核实依据。
- 数据库对已入账退货、有关联退货的原销售明细、对账归属和退款凭据增加保护；应用层的状态检查、累计限额和事务仍同时执行。

上线时仍建议保留一次可恢复的数据备份。本次不部署服务器，也不修改生产数据库。
