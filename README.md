# 极简进销存系统

面向 5 人小团队的最小化进销存系统：多仓库管理、仓库间调拨（支持车销小库房场景）、箱/瓶双单位换算、采购入库、销售出库、库存实时结存、库存预警、角色权限（管理员 / 操作员）。

- 后端：Node.js + Express
- 数据库：SQLite（单文件，`data/jxc.db`，备份=复制文件）
- 前端：服务端渲染（EJS）+ 原生 JS，无需单独构建
- 部署：Docker，可直接接入你现有的 Nginx Proxy Manager 反代

---

## 一、快速部署（Docker，推荐）

把整个 `jxc-app` 文件夹上传到你的 Oracle Cloud 服务器，比如 `/opt/jxc-app`，然后：

```bash
cd /opt/jxc-app
cp .env.example .env
# 编辑 .env，把 SESSION_SECRET 改成一串随机字符串（例如用 openssl rand -hex 32 生成）

docker compose up -d --build
```

启动后，服务监听在 `127.0.0.1:3000`（只绑定本机，不直接暴露公网，这一点和你现有服务的安全策略一致）。

## 二、接入 Nginx Proxy Manager

在 NPM 里新增一个 Proxy Host：
- Domain：比如 `jxc.你的域名.com`
- Forward Hostname/IP：`127.0.0.1`（如果 NPM 和这个容器不在同一 Docker 网络，用宿主机 IP）
- Forward Port：`3000`
- 开启 SSL，用 Let's Encrypt 自动签发即可

## 三、首次登录

默认管理员账号：`admin` / `admin123`

**登录后请立刻在右上角"修改密码"里改掉默认密码。**

首次启动会自动建一个"总仓"仓库，可以在"仓库管理"里改名或新增更多仓库/门店。

## 四、账号与权限

在"账号管理"（仅管理员可见）里给团队其他 4 个人开账号，分两种角色：

- **管理员**：商品档案（含成本价）、供应商、采购入库、仓库、账号管理、销售，全部权限
- **操作员**：只能看商品售价（看不到成本价），只能做销售出库和查库存，无法访问采购模块和采购价

## 五、箱 / 瓶双单位

商品档案里可以设置"基本单位"（比如瓶）+"大单位"（比如箱）+ 换算比例（比如 1 箱 = 24 瓶）。库存内部统一按基本单位计数，采购/销售/调拨单据上可以按箱或瓶自由选择录入，系统自动换算，库存页面会同时显示"480 瓶（≈20箱）"这样的换算结果。

如果某个商品不需要大单位，新增商品时"大单位"留空即可，只按一个单位使用。

## 六、仓库调拨（车销/小库房场景）

把每辆车、每个门店都建成一个"仓库"（仓库管理里新增，比如"车1""车2"），然后用"调拨"功能把货从总仓挪到车上——库存会从总仓扣减、同时加到车1，全程留痕，不会污染采购/销售的价格和统计数据。调拨不涉及价格，管理员和操作员都可以操作。

出车回来清点剩货，如果有退货，同样可以用调拨从车1调回总仓。

## 七、日常使用流程

1. 商品管理 → 录入商品（名称、基本单位、大单位换算、成本价、售价、库存预警阈值）
2. 仓库管理 → 建好总仓、各车/门店的仓库
3. 采购入库 → 选供应商、仓库，录入采购明细（可按箱或瓶）→ 自动加库存
4. 调拨 → 把货从总仓挪到车上/门店
5. 销售出库 → 选客户、仓库，录入销售明细（可按箱或瓶）→ 自动减库存，库存不足会拦截
6. 库存查询 / 出入库流水 → 随时核对，支持按仓库筛选
7. 首页看板 → 今日销售额、库存预警提醒、最近销售单

## 八、数据备份

数据全部在 `data/jxc.db` 一个文件里，定期复制这个文件就是完整备份：

```bash
# 建议加到服务器的 crontab，比如每天备份一次
cp /opt/jxc-app/data/jxc.db /opt/backups/jxc-$(date +%Y%m%d).db
```

## 九、本地开发/不用 Docker 运行

```bash
npm install
node app.js
# 默认监听 http://localhost:3000
```
